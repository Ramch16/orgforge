# Vittics Builder 0.20.1 — set up from the app

In 0.20.0, a fresh install could not be set up without a terminal: it started on the Anthropic API
with no way to enter a key, and the desktop app could not switch the agents to a subscription, so the
first piece of work failed. 0.20.1 fixes that.

- **A banner on every page** while the agents cannot work, saying why (for example "No Anthropic API
  key yet", or "Claude Code is not signed in").
- **How your agents think**, on the Machine page: Claude Code (your Claude subscription), Codex
  (your ChatGPT plan), an Anthropic API key, or the offline demo, each with its install and sign-in
  status. **Use this** moves every agent to it, and new hires use it too. **Test** sends one tiny
  prompt to prove it answers.
- **API keys stay private.** A key entered in the app is stored in the company folder (owner-only),
  loaded into the server only, and never reaches agents' commands, the product's checks, the activity
  log or anything the dashboard returns.
- The choice is kept in the company's database; `org.yaml` and its comments are never rewritten.
- The same from a terminal: `vittics-builder ai`, `ai use claude-code|codex|api|demo`, `ai key`,
  `ai test`.

Upgrading keeps what an existing company already uses; it is shown as the current choice until you
pick another.

The installers are not signed: Windows SmartScreen and macOS Gatekeeper warn on first open (Windows:
More info, then Run anyway; macOS: Control-click the app, then Open). The Windows app has not yet been
opened on a real Windows PC.

Validation includes 293 offline tests on Linux (Python 3.11 and 3.12) and macOS, 285 on Windows (the
rest need optional extras), and the setup flow tried in a browser as a new install: the banner, choosing
Claude Code in one click, and a real test prompt answered through Claude Code.
