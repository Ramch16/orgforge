# Vittics Builder 0.20.0 — Idea to production

Describe what you want in a sentence and choose how hands-on to be. The team assesses the idea,
plans it, writes requirements, designs, builds and reviews it, runs the release checks, and after
your sign-off runs it on this computer.

```bash
vittics-builder build "A customer support app with login, a database and Stripe payments" --autopilot key
```

Or type it into **What do you want to build?** on the dashboard's Home page.

- **Autopilot, per project.** `off` (you approve every stage), `key` (the default: you decide the
  idea, the plan and the final sign-off) or `final` (only the final sign-off). Only routine gates can
  be automatic, and only when their conditions hold: the technical sign-off, the idea decision when
  the assessment recommends building, the plan, requirements, design, and the release review, which
  exists only once audits, acceptance checks and executable verification have passed. Failures,
  changed acceptance checks, budgets, hiring, installs, deployments and the final sign-off always
  wait for a person. The sign-off lists everything autopilot decided, and why; autopilot never
  scores agents.
- **Preparing this computer.** Building waits when the machine lacks what the project needs, with
  the commands to install it.
- **Keys for the product.** API keys and database URLs are stored privately per project (not in the
  database), given to the product's checks, preview and deploy commands, and replaced with `[NAME]`
  in any output, including the committed verification report. Agents see the names, never the values.
- **A preview on this computer.** A web app or API with `serve` in its `product.json` runs here
  after sign-off (when no `production:` entry exists), from a clean copy of the release,
  health-checked and linked from its project page. A new version replaces the old one only once it
  answers; if it fails, the old one keeps running and the CTO decides. Previews stop with the server
  or the desktop app.
- **One card per project** for autopilot, the preview and keys.

Existing companies receive additive database migrations; existing projects stay on step-by-step
autopilot. Back up company data before upgrading.

Not yet verified: the whole path from a sentence to a running preview with real AI agents (it was
exercised with the offline agents, and the preview with a real web server). The installers are not
signed: Windows SmartScreen and macOS Gatekeeper warn on first open (Windows: More info, then Run
anyway; macOS: Control-click the app, then Open). The Windows app has not yet been opened on a real
Windows PC.

Validation includes 286 offline tests on Linux (Python 3.11 and 3.12) and macOS, 278 on Windows
(the rest need optional extras), real preview processes started, health-checked, replaced and
stopped on every platform, and the dashboard flow from a sentence to sign-off with keys and a
preview tried in a browser.
