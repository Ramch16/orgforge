# Vittics Builder 0.21.0 — checks run on your computer

Agents on Codex (and other sandboxed coding tools) could not run a product's checks: their sandbox blocks
Docker, databases, local ports and browsers. Release QA reported "permission denied" instead of results, so
releases stayed blocked, ticket reviews kept sending finished work back, and agents were scored down and
replaced for it.

Now Vittics Builder runs the product's checks (`product.json`) itself, on this computer:

- **Before release QA.** Real failures go straight back to Engineering with the real output. When the checks
  pass, QA reviews with the results in hand instead of trying to run them in its sandbox.
- **Before each ticket review.** Reviewers see which checks passed and the end of any failure, and are told
  not to send work back only because their own sandbox could not run something. Turn this off with
  `pipeline.review_checks: false` in `org.yaml` if your checks are slow.
- **Only the checks the CTO approved run.** If the team changes them, the change goes to the CTO first.
- Each check may run for up to 30 minutes (`pipeline.check_timeout`, in seconds) instead of the agents' 5.

Keep Docker Desktop running for projects that use it; nothing in Docker needs to change. The desktop app
also finds Docker Desktop's command in `~/.docker/bin`.

## Install

- **macOS (Apple Silicon):** Quit Vittics Builder, open the DMG, and drag the app into Applications. Choose
  Replace if prompted. If macOS cannot verify it, use System Settings → Privacy & Security → Open Anyway.
- **Windows (x64):** Quit Vittics Builder and run the setup installer.

Existing company data is kept. Projects already in progress pick this up at their next ticket review or
release check: click **Resume work**, or send back a blocked release.

The source tests (299) passed locally on macOS; CI runs them on macOS, Windows and Linux, and the installer
builds smoke-test the bundled backend.
