# OrgForge 0.18.0

OrgForge now prepares the computer it runs on, spreads work across your other computers, comes as a
desktop app, and runs on Windows. This release includes 0.15, 0.16 and 0.17, which were built in
sequence and are released together.

- Machine readiness (0.15): `orgforge doctor` and a Machine page show what the company and each
  project need (from agents' engines, project files, `product.json` and production commands), what
  is installed, whether Docker is running and whether the AI CLIs are signed in. Missing tools
  install from a fixed catalog with Homebrew, winget or npm, one at a time after you confirm;
  admin-only installs are shown as commands to run. Failed checks that hit "command not found" now
  name the missing tool.
- Worker machines (0.16): other computers run agents' coding CLIs on their own logins. Workers pair
  with a one-time code proven both ways without sending it, connect out (no open port), and sign
  every request and reply; jobs name an engine, never a command, and changes come back as patches
  reviewed here. An offline worker hands its turn back to this computer.
- Desktop app (0.17): a Tauri app with a bundled backend on 127.0.0.1, automatic sign-in, a CEO/CTO
  switch and a first-run welcome. It finds Homebrew tools and AI CLIs when opened from Finder and
  stops its backend when it quits.
- Windows (0.18): commands run in Git Bash; npm `.cmd` wrappers are bypassed so cmd.exe never
  re-reads agents' prompts, and other batch wrappers are refused when arguments could inject
  commands. Fixed: legacy text encoding (the dashboard did not load), unpinned arena fixtures,
  changed line endings and backslash paths. Tests run on Windows, macOS and Linux in CI, and a
  workflow builds the Windows installer and macOS dmg.

Existing companies receive additive database migrations. Back up company data before upgrading.

The installers attached to this release are not signed: Windows SmartScreen and macOS Gatekeeper
warn on first open (Windows: More info, then Run anyway; macOS: Control-click the app, then Open).
The Windows app has been built and its backend smoke-tested in CI, but not yet opened on a real
Windows PC. Worker machines were tested between two processes on one Mac, not across computers.
Gemini and the other CLI engines besides Claude Code and Codex remain untested. winget and apt
install paths follow their documentation and have not been run.

Validation includes 262 offline tests passing on Linux (Python 3.11 and 3.12), macOS and Windows,
a real Codex task run through a worker, the desktop app opened and quit on macOS, and the bundled
backend smoke-tested on Windows and macOS.
