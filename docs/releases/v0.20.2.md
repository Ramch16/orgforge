# Vittics Builder 0.20.2 — the macOS app opens

The 0.20.1 macOS app could not be opened: macOS said **"Vittics Builder.app is damaged and can't be
opened"**. Its signature did not cover the whole app, and macOS treats a downloaded app with a broken
signature as damaged. 0.20.2 fixes the signature. Also:

- If macOS stops the app's backend before it starts (it does that to apps you have not approved yet),
  the loading screen now says so and shows how to allow it, instead of an empty "could not start".
- The loading screen and the dashboard's logo placeholder said "O", left over from OrgForge; now "V".

**Opening it the first time on a Mac** (it is not yet signed with an Apple Developer ID):

1. Open the `.dmg` and drag **Vittics Builder** to Applications.
2. Open it. macOS says it cannot verify the app: click **Done**.
3. Open **System Settings → Privacy & Security**, scroll down, and click **Open Anyway** next to
   Vittics Builder. Confirm. You only do this once.

**Already installed 0.20.1?** Replace it with this version. Or, to keep 0.20.1, run these two commands
in Terminal and then open it normally:

```bash
codesign --force --deep --sign - "/Applications/Vittics Builder.app"
xattr -dr com.apple.quarantine "/Applications/Vittics Builder.app"
```

**On Windows**, nothing changed: when SmartScreen says "Windows protected your PC", click **More info**,
then **Run anyway**. Git for Windows must be installed.

How it was checked: the app's signature now passes `codesign --verify --deep --strict`, both as built
and inside the `.dmg`; macOS's own check now reports the usual "rejected" for an app that is not
notarised (0.20.1 reported a broken signature); and the bundled backend starts from inside the signed
app. These checks now run in CI on every build. The hardened runtime stays off until the app is
notarised: with it on, macOS stops the bundled Python from loading, so the app opened but never
started.
