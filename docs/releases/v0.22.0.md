# Vittics Builder 0.22.0 — checks during repairs

Version 0.21.0 ran host checks before review, but coding agents still attempted Docker in their own restricted session while implementing repairs. They could submit blocked work without receiving a real test result.

Builders and QA now request selected check IDs from the CTO-approved product.json. Vittics runs those commands under the existing workspace policy and resumes the agent with their actual output. CLI sandbox permissions stay unchanged. Two request/repair continuations are allowed per assignment; unresolved work remains subject to review. Host results are retained in run history.

Ticket-review checks now also reject an unapproved changed contract before executing it. Agents receive valid staffed role IDs when filing tickets, and long approval summaries preserve the failure tail.

## Install

Quit Vittics Builder, open the macOS DMG and replace the app in Applications, or run the Windows installer. Company data is retained. Keep Docker Desktop running and resume the project after reopening Vittics. Already-running agent sessions must finish before the new workflow applies.

This release repairs the builder workflow. Customer Support App security, capacity and real-data approvals still require their own observed evidence and review.
